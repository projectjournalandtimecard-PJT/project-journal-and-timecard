Project Journal & Timecard (PJT) keeps track of your projects, section budgets against actuals, preparer and reviewer notes, open items, and where your day went — in one self-contained app. Your data lives on your own machine. Cloud sync is optional and self-hosted: there is no PJT server, and nobody (the author included) receives your data.
About this app
PJT is one HTML file in a small native shell. That is the whole architecture, and most of what follows is a consequence of it.

Three tabs across the top: Project Journal (workpaper sections, budgets, notes, open items), Time Card (log your day, roll hours into project sections), and Daily W.I.N. (a short "What's Important Now" list). Two pocket tools live in the header — a ▦ scratch sheet and a 🔔 focus timer.

Everything saves as you go; the dot at top right reads Saved after each change. Nothing leaves your machine unless you deliberately turn on cloud sync.

Being one file makes it hard to truly break. If a build ever misbehaves, an older installer opens the very same data.
Installing
Downloads are on the project's GitHub Releases page: a .exe for Windows and a .dmg for Apple Silicon Macs.

The installers are unsigned, so both operating systems will ask you to confirm before running one. A signing certificate is a yearly cost and this is a free tool. The prompt means the publisher could not be verified automatically; it is not the result of any check finding a problem with the file.

Windows. If a blue box appears, click More info, then Run anyway.

macOS. If the app does not open on a double-click, right-click it in Applications and choose Open, which offers the option to continue. macOS describes unsigned apps as "damaged", which refers to the missing signature rather than to the file itself. If that route does not work, open Terminal and run xattr -dr com.apple.quarantine "/Applications/Project Journal & Timecard.app", then open the app normally.

If unsigned software is not permitted at your firm, the whole app is one readable file (src/index.html) and you can build it yourself from source.

Installing over an existing copy is safe. Your data is stored separately and survives upgrades and uninstalls.
Quick start
Five minutes, and you can skip steps 4 and 5 indefinitely.

1. The ★ ACME Co — Example project is invented sample data. Poke at it; you can't hurt anything.
2. Click the three tabs to see the shape of things.
3. When you're ready for real work: select the ACME example, Delete Project, then New Project for your own.
4. Optional — set up cloud sync. Skip it and the app still saves locally and backs itself up.
5. Optional — turn on a passphrase to protect the file on disk.
Project Journal
Creating projects. New Project offers the built-in Audit Template, a Blank Project, or any section template you've saved. A project has a name, an optional Time-card client code that links it to your time card, a role (Preparer / Reviewer / Both), and free-form Project Notes.

Sections. Each row is a workpaper section with a Status (In Prep → Tech Review → Review Comments → Complete), Budget, Actual, automatic Variance, Preparer Notes, Reviewer Notes, and Open Items. Expand any note for a larger editor, or press Copy to lift its text.

Stat cards across the top total the project live: budget, actual, variance, sections complete, open items.

Project actions sit in the left panel — Rename, Duplicate Project, Copy to New Year (a fresh copy with actuals cleared), Add Custom Section, Section Templates…, Delete Project, and an Archived toggle that hides finished work from the pickers without deleting it.

Getting things out. Export Project Markdown produces a clean text summary. Copy Open Items grabs just the open items, which is the one you'll use most — the preview shows your bold, italic and red exactly as you wrote them, and pasting into Word or Outlook keeps the formatting. Search sections, notes… filters within the open project.
Time Card
The one rule: set only the code and the stop time. Each block starts where the previous one stopped, so the day is a chain and you never type a start time at all.

Reordering. The ▲ ▼ buttons move a block. Because starts come from position, every time and duration recalculates itself. Nothing to re-enter.

Codes. Each day carries its own code list — a letter, a client or description, and a type (billable, non-billable, unpaid). Carry codes forward copies yesterday's. A code linked to a journal section shows that section beside it in the dropdown.

Journal sync. Hours on a code linked to a project section roll into that section's Actual automatically. Always on, no button to remember. Re-syncing a day replaces that day's contribution rather than adding to it, so it cannot double-count.

Month Report totals by client and type for the month and gives you a copyable summary. Click any row to see its entry notes alongside the linked journal notes.

The 🔔 on a row starts the focus timer for that block, already set to the right length.
Daily W.I.N.
A short "What's Important Now" list for each day — the handful of things that actually matter today, with a progress count.

It is deliberately small. This is a focus list, not a task manager, and it stops being useful at about the point it stops fitting on one screen.
Formatting notes
Every note field is a rich-text box. Select text and press Ctrl+B or Ctrl+I, or open the note with Expand ↗ for the full toolbar: bold, italic, strikethrough, a red swatch, a back-to-default swatch, and bullets. A button fills in when its effect is active where your cursor is.

Formatting is stored as Markdown behind the scenes, which is why exported and copied text stays readable anywhere, and why red survives the trip into Word or Outlook. Pasting from another app keeps your text and drops its formatting, which is almost always what you wanted.

The expanded editor saves as you type. Close it however you like — the Close button, Escape, clicking outside — and your edit is kept.
▦ Scratch sheet
The ▦ button in the header opens a small spreadsheet over whatever you're doing, for the arithmetic you'd otherwise scribble on a sticky note. Eight columns (A–H) by 25 rows.

Formulas start with = and handle + - * /, parentheses, and SUM, AVG, MIN, MAX over ranges like =SUM(A1:A9). Blank cells and text count as zero, the way a napkin would.

Building formulas by pointing. After typing =, press ↑ or ↓ and the arrows steer a cell reference instead of moving you out of the cell; the referenced cell lights up. Type an operator and the next arrow starts a fresh reference. So = ↑ + ↑ ↑ adds the two cells above. Clicking a cell mid-formula does the same thing.

Errors show as #DIV0, #CYCLE, #REF or #ERR. Your typed text is never eaten, so you can always see what you meant and fix it.

Moving numbers to Excel. Drag across cells, or hold Shift and use the arrow keys, to select a block; Ctrl+A takes the whole sheet. Ctrl+C copies it in the format Excel, Google Sheets and Numbers expect, so it pastes in as real cells rather than one lump of text. Formulas are copied as their results — PJT's formula names are close to Excel's but not identical, and a formula that silently meant something different in the other program would be worse than a number. Pasting a block of cells the other way, from a spreadsheet into the sheet, works too.

It is temporary on purpose. The scratch sheet is not saved with your journal, never syncs, and clears when you close the app. It is a napkin, not a workpaper. Anything worth keeping should be moved into a note.
🔔 Focus timer
A countdown for working in blocks. Set the minutes and press Start, or press the 🔔 on a time-log row to time that particular block. The grid drains as time passes, which is easier to read at a glance than digits.

Pop out ↗ floats the timer in its own small always-on-top window so it stays visible while you work in another app. Both windows stay in step, and either one can start, pause, or reset.

Sound is off by default. Turned on, it rings once when time is up. Never repeatedly, never again thirty seconds later.

The timer keeps no history and stores nothing at all.
Custom sections & templates
The built-in Audit Template reflects one firm's workpaper set. Most audit practices are close to it, and yours will differ somewhere — so nothing about it is fixed.

Adjust one project: Add Custom Section adds a row, and sections can be renamed or deleted freely.

Reuse it everywhere: once a project's section list looks right, open Section Templates… and choose Save current sections as template. Name it something you'll recognise later, like "Firm Audit — 2026". It then appears in the New Project dropdown. You can keep up to five.

A template stores section names and nothing else — no budgets, notes, hours, or client data. That is what makes templates safe to carry around in a synced journal.

Grouping. Sections sort themselves into groups by their leading letter or number. Naming one B - Receivables files it under Assets automatically; anything unrecognised lands in Custom, which is a perfectly respectable place to be.

Where your data is stored
Desktop app: a journal.json file in the app's own folder, with a backups folder beside it. The exact path is shown under ⚙ → Local storage. It survives upgrades and uninstalls.

In a plain browser: browser local storage instead. Worth knowing that this is per browser profile — the same app opened under a different profile shows a different, empty journal. It looks exactly like data loss and isn't. The desktop app sidesteps the whole problem.

No database, no server, no account. You can copy, back up, or read the JSON file yourself.
Backups & restoring
Automatic: the desktop app writes a dated backup each day it's used and keeps the newest 30, in the backups folder next to your data.

Manual: ⚙ → Export / Backup writes a JSON file you can put anywhere. Do this before anything you'd describe as "a bit of a cleanup", before moving machines, and before any experiment.

Restoring: ⚙ → Import / Restore and pick a backup file. It replaces the current journal, so export first if there is anything in there you want to keep.

Team credentials are stripped from every export. Backups are safe to email or store without leaking your token.
Encryption — and what it does not cover
What it is. ⚙ → Encryption puts your local data file behind a passphrase using AES-GCM. This protects a lost or stolen laptop: without the passphrase, the file on disk is unreadable.

Turning it on gives you a one-time Recovery Key. Put it somewhere separate from the passphrase — a password manager is ideal. A forgotten passphrase is recoverable with the Recovery Key. Losing both means the data is gone, with no reset and no appeal, because there is no server holding a copy.

What it does not do: it does not encrypt what you push to cloud sync. The local key is derived from your passphrase on your machine, so nobody else could read a file encrypted with it — which is precisely what sync needs to do. Synced content is therefore stored as plain readable JSON in your gist.

So a passphrase protects your laptop. It does not make what you sync private. The next two sections cover that.
Cloud sync — setting up your own
Sync is self-hosted: it uses your GitHub gist as the storage. There is no PJT server and nobody else's infrastructure involved. It exists so one person can work across two machines, and so a small team can share a journal.

You do this once, and only if you want sync at all.

1 — Make a GitHub account for it. Free. Use a dedicated account rather than your personal one: the access token you create gets shared with teammates, and you don't want that reaching into your own repositories.

2 — Create the gist. Signed in, go to gist.github.com. Put anything in the filename and body. Click Create secret gist. The long hex string at the end of the resulting URL is your gist ID — copy it.

3 — Create an access token. GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic). Name it "PJT". Set an expiry you'll remember. Tick only the gist scope and nothing else. Generate it, then copy it immediately — GitHub shows it exactly once.

4 — Connect PJT. ⚙ → Cloud Sync → the First-time setup (admin)? box → paste the gist ID and the token → Connect. PJT checks both against GitHub straight away and tells you which one is wrong if either is.

5 — Save your Team code. A PJT1-… string appears. That single code carries the gist ID and token together; it is how you onboard anyone else and how you reconnect a new machine. Treat it exactly like a password — password manager, not email. Anyone holding it can read and write everything in that gist.

6 — Add a teammate. Give them the Team code out of band, then have them use Join an existing journal with their own Journal ID.

When the token expires sync stops. Generate a new token, reconnect through the admin box, and hand out the new Team code. Nobody reinstalls anything.

Conflicts. If the same journal changed in two places, PJT asks which copy to keep rather than guessing and being wrong half the time.
Privacy — what to keep out of the cloud
This matters more in an accounting practice than in most software, so it is stated plainly rather than buried.

If you never turn on cloud sync, none of this applies. Your data never leaves your machine.

If you do turn it on: what you sync is stored as readable JSON in your GitHub gist. A secret gist is unlisted, not private — the protection comes from the URL and the token staying secret. In practice it can be read by anyone with your Team code, anyone who gets into that GitHub account, and GitHub itself.

So keep client-identifying detail out of anything that syncs. Section budgets, hours, statuses, and shorthand notes are fine. Client names, contact details, financial figures, and anything you wouldn't put in a personal email are not.

The Time-card client code is a useful habit here: a short code like ACME R carries the meaning for you without spelling anything out for anyone else.

Whether this arrangement is acceptable at all is a professional judgement for your firm, not a technical one. If in doubt, ask whoever owns confidentiality policy — or simply don't enable sync. The app is fully functional without it.
FAQ & troubleshooting
Windows says the installer is unrecognised. Expected — it's unsigned. More info → Run anyway.

macOS says the app is damaged. Also expected, and also just the unsigned-app message. Right-click the app → Open. See Installing for the Terminal fallback.

My data vanished. Almost always the wrong place rather than lost data. In a browser, check you're in the same profile. In the desktop app, check ⚙ → Local storage for the path, and look in the backups folder beside it.

Sync says it can't connect. Usually an expired or wrongly-scoped token. Regenerate it with the gist scope ticked and reconnect through the admin box.

A teammate can't see my journal. They need the Team code and their own Journal ID, then Join an existing journal.

I forgot my passphrase. Use the Recovery Key. Without both, nobody can recover the data — not you, not the author.

Hours aren't reaching a section. The time-card code has to be linked to that project section, and the project needs a matching client code.

The scratch sheet emptied. By design; it never persists. Move anything worth keeping into a note.

The timer popout stopped responding. Close it and pop it out again. Both windows can drive the timer, so the main window's controls keep working regardless.

Something looks broken after an update. Export a backup, then install the previous version. Your data file is unchanged and older builds read it quite happily.
Get AI help
If something is wrong and nothing above covers it, PJT can write a summary of itself that you can paste into ChatGPT, Claude, Gemini, or any other AI assistant. Because the whole app is one file with no server, the context needed to troubleshoot it is small enough to hand over in a single message.



The packet describes what PJT is, how it stores data, which version and platform you are running, and the failure modes that are already known. It ends by asking the assistant to check with you before suggesting anything that deletes or overwrites data.

On confidentiality. The packet contains counts only — how many projects, how many sections, whether sync is on. It never includes project names, client codes, note text, hours, your Team code, or your token. Those fields are not filtered out; they are never read in the first place.

You will see the exact text before anything is copied. Read it. You are the one bound by a confidentiality obligation, and a chat assistant is a third party like any other — if your firm has a policy on AI tools, it applies here too.
For developers & maintainers
PJT is open source under the MIT licence — use it, change it, ship it, at no cost and with no warranty. The whole app is src/index.html: HTML, CSS and JavaScript in one file, no build step, no framework, no dependencies. Open it in a browser and it runs.

Building the desktop apps. The repo wraps that file with Tauri 2 and builds on GitHub Actions — an NSIS .exe on a Windows runner and a .dmg on an Apple Silicon runner, in one matrix, with no local toolchain. Push to main to get artifacts; push a v* tag to get a draft Release with both installers attached. Bump version in tauri.conf.json, and note it must be strict semver — 3.10.0, never 3.10.

MSI is deliberately absent: WiX's candle.exe chokes on the ampersand in the app name. NSIS is the stable Windows target.

Storage uses tauri-plugin-fs, scoped by a capability file to the app's own data folder, so nothing else on disk is reachable. It is feature-detected, so the same file still works in a plain browser.

Encryption is Web Crypto (AES-GCM + PBKDF2), no libraries: a passphrase-derived key wraps a random data key, and a Recovery Key wraps the same data key.

Cloud sync is one gist holding one JSON file per person, reached with a runtime Team code. No credential is ever committed or shipped, which is why the repo can be public. Synced content is stored as plaintext JSON, which is why the Privacy section asks you to keep client-identifying detail out of anything that syncs.

Design constraints worth preserving: no servers, no third-party data services, no telemetry, no accounts, one portable file, minimal toolchain. Anything that would stop the app working offline, or start it reporting home, is against the grain of the thing.
